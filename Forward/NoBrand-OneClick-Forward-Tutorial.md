## 一、转发后端选型：Realm 与 nftables 怎么选？

NoBrand-OneClick 脚本同时适配了 **Realm（高性能用户态中继）** 与 **nftables（Linux 内核级 NAT）** 两种转发引擎。

脚本对两者都做了高度自动化封装，**无论选择哪一种，都没有任何繁琐的手动命令**（内核参数开启、回程路由伪装 MASQUERADE、守护进程创建等全部由脚本全自动搞定，小白轻松使用）。

### 核心区别与快速选型建议

| 对比维度 | Realm（用户态中继，🌟小白推荐） | nftables（内核级 NAT，⚡性能优先） |
| :--- | :--- | :--- |
| **转发工作层级** | 用户态套接字转发，自带断线自愈 | Linux 内核网络栈直接转发，零拷贝 |
| **目标地址支持** | **支持域名（自带 DNS 动态解析）**、IPv4、IPv6 | **支持 IPv4、IPv6** |
| **系统与环境依赖** | 独立二进制，零系统依赖，任何容器/系统均可 | 依赖系统内核 `nf_tables` 模块 |
| **回程配置难度** | 全自动（目标机天然正常回包） | **全自动**（脚本默认自动开启 MASQUERADE） |
| **适用场景推荐** | **落地机使用域名、或 IP 会变动的场景** | **追求极低资源开销、目标为固定 IP 的场景** |

> 💡 **极简选型建议**：
> * **如果目标填的是域名（如 DDNS / CDN 域名）** → **选择 Realm**（nftables 不支持动态解析域名）；
> * **如果目标填的是固定 IP** → **两者均可**。脚本都会自动配置好回程 MASQUERADE；追求极低 CPU 与内存占用时，可选 nftables。

### 第三步：规则命名与后端选择（推荐 Realm）

```text
规则名称: cmix-sg
转发后端: 1) nftables - 内核 NAT (简单 IP 转发)
         2) Realm - 用户态中继 (域名 / 高级转发)

```

> 💡 **参数注释**：
> * **规则名称**：任意英文或数字标识，例如 `cmix-sg`（表示通过 CMIX 专线转发到新加坡落地）。
> * **转发后端**：**直接输入 `2` 选择 Realm**。

---

### 第四步：选择传输协议

```text
协议: 1) TCP  2) UDP  3) TCP + UDP
请选择 [1-3]: 3
```

> 💡 **参数注释**：
> * **输入 `3`**：同时开启 TCP + UDP 转发，既能满足常规上网与视频浏览（TCP），也能完美兼顾语音通话、游戏和 QUIC 协议（UDP）。

---

### 第五步：填写本地监听端口（必看说明）

```text
监听地址 [0.0.0.0]: 
监听端口: 7490
```

> 💡 **操作要点**：
> * **监听地址**：直接敲回车，保持默认 `[0.0.0.0]`。
> * **监听端口**：**必须填写 NoBrand 控制面板分配给您的 100 个内网端口之一**（例如面板分配端口范围为 `7400-7499`，此处可填写 `7490`）。

---

### 第六步：填写目标落地服务器地址与端口

```text
目标地址: 216.195.x.x
目标端口: 49386
备注 (可选) : 
```

> 💡 **参数注释**：
> * **目标地址**：您外部真正落地的节点地址。可以是 **IPv4 地址**（如 `216.195.x.x`），也可以直接填写 **域名**（如 `sg-node.yourdomain.com`）。
> * **目标端口**：落地服务器上对应协议节点的真实监听端口（如 `49386`）。
> * **备注**：可选，直接敲回车留空即可。

---

### 第七步：Realm 高级选项处理

```text
配置 Realm 高级选项? [y/N]: y
出站 IP / through (留空使用系统默认) : 
出站网络接口 (留空使用系统默认) : 
监听网络接口 (留空使用系统默认) : 
DNS 服务器 (逗号分隔; 留空使用系统默认) : 
额外目标 host:port (逗号分隔; 留空表示无) : 
```

> 💡 **小白快速通行技巧**：
> * **最简方式**：此处直接输入 `n`（或直接敲回车），直接跳过高级设置。
> * **如果不小心输入了 `y`**：无需惊慌，如图所示，随后的每一个高级选项（出站 IP、网卡、DNS、额外目标）**全部一路直接敲回车**，系统就会自动全部采用系统最优默认值。

---

### 第八步：配置客户端入口（核心避坑步骤）

```text
Port Forward 真实监听端口: 7490
客户端入口建议: 87.86.x.x:7490
  1) 使用自动入口 (以后查看节点时重新探测 host; 端口等于真实监听)
  2) 自定义客户端入口 (IPLC / NAT / DNAT)
请选择 [1-2, 默认 1]: 2
客户端入口 Host [87.86.x.x]: 211.136.x.x
客户端入口 Port [7490]: 
```

{% hint style="danger" %}
**重要避坑指南（不能直接回车选 1）**：

* **原因**：脚本在服务器内部探测到的 IP（如 `87.86.x.x`）均为宿主机出口地址，**直连会导致绕过专线**！
* **正确做法**：
  1. 输入 **`2`** 选择“自定义客户端入口”。
  2. 在 `客户端入口 Host` 处，**手动粘贴 NoBrand 网页控制面板中明确标注给你的【移动入口 IP】**（例: `211.136.x.x`）。
  3. 在 `客户端入口 Port` 处，敲回车使用默认的对应端口（如 `7490`，脚本会自动回填上一步写入的端口）。
{% endhint %}

## 三、实战二：nftables 转发配置（内核原生/高性能）

如果您的目标落地机使用的是固定 IP，并且追求 Linux 内核级的低延迟与高吞吐，选择 **nftables** 同样非常便捷。脚本会自动配置好内核参数与回程 SNAT，完全不需要任何繁琐的手动命令。

### 第一步：规则命名与选择 nftables 后端

在端口转发子菜单中输入 `1` 添加规则，后端选择 `1`：

```text
规则名称: cmix-hk-nft
转发后端: 1) nftables - 内核 NAT (简单 IP 转发)
         2) Realm - 用户态中继 (域名 / 高级转发)
请选择 [1-2]: 1
```

---

### 第二步：协议、监听与目标设定

```text
协议: 1) TCP  2) UDP  3) TCP + UDP
请选择 [1-3]: 3
监听地址 [0.0.0.0]: 
监听端口: 7491
目标地址: 103.200.x.x
目标端口: 19138
备注 (可选) : 
```

> 💡 **参数注释**：
> * **监听端口**：同样输入 NoBrand 面板分配给您的 100 个内网端口之一（如 `7491`）。
> * **目标地址**：填写落地机对应的有效 IP 地址（如 `103.200.x.x`）。

---

### 第三步：源地址模式选择（全自动 MASQUERADE）

```text
源地址模式: 1) MASQUERADE (默认)  2) Preserve Source (高级; 目标端需要正确回程路由)
请选择 [1-2, 默认 1]: 1
```

> 💡 **省心提示（直接回车选 1）**：
> * **推荐直接敲回车（默认 1 MASQUERADE）**：脚本会自动下发内核 SNAT 地址伪装，落地目标机收到的包源地址为本中转机 IP，目标机无需任何额外设置就能自动顺畅回包。
> * **不要选 2**：Preserve Source 保留真实客户端 IP，要求目标落地机必须配置专门的静态策略路由把流量送回本中转机，否则无法通网。

---

### 第四步：配置客户端入口并自动加载内核规则

```text

客户端入口建议: 87.86.x.x:7491
  1) 使用自动入口 (以后查看节点时重新探测 host; 端口等于真实监听)
  2) 自定义客户端入口 (IPLC / NAT / DNAT)
请选择 [1-2, 默认 1]: 2
客户端入口 Host [87.86.x.x]: 211.136.x.x
客户端入口 Port [7491]: 
```

输入完毕后，脚本自动完成内核状态核验与规则应用：

```text
[INFO] 正在启用系统内核参数: net.ipv4.ip_forward = 1

按回车返回主菜单...
```

脚本自动为您开启了 `net.ipv4.ip_forward = 1` 内核转发参数，并完成了 nftables 规则的原子下发，整个过程与 Realm 一样丝滑，无需手动敲击任何 Linux 底层防火墙命令。

## 四、日常管理与多规则运维

进入端口转发子菜单（主菜单输入 `8`），即可使用完善的管理功能：

### 1. 查看规则列表与状态
在子菜单输入 `2`，以表格形式清晰罗列所有规则：
```text
ID                 名称                 后端       协议   实际监听               强制策略    目标                          状态
f260de9a1f43f0b50  cmix-sg              realm      both   0.0.0.0:7490           permissive  216.195.x.x:49386             已启用
```

在子菜单输入 `3`，输入规则名称（如 `cmix-sg`），可以查看完整的展示端点、监听端点以及运行健康状况。

在子菜单输入 `10`，脚本会自动对端口转发进行全栈体检：
- 状态文件与配置合法性检测
- 端口所有权与冲突检测
- Realm 与 nftables 规则与守护进程活跃性检测

## 五、核心避坑指南

1. **内网端口必须在分配区间内**：
   NoBrand 每台机器分配了固定的 100 个端口段。转发规则的“监听端口”必须严格位于该端口段内，填错将导致外部流量无法穿透进来。
2. **目标服务器防火墙放行**：
   确保您的目标落地机（如 `216.195.x.x:49386`）的安全组/防火墙已经放行对应端口，并且落地服务已正常启动。
3. **落地机协议选择**：
   由于国内入口对常见代理协议有特征过滤，专线中转推荐搭配 Mieru 或专线允许的传输协议，保障长久稳定。
