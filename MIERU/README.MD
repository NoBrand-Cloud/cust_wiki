## 一、NoBrand 专线产品特性与必知常识

### 1. 网络拓扑与产品线划分

NoBrand 提供的网络线路属于**内网专线**。根据产品线架构的不同，其网络拓扑分为两种：

#### (1) 单 CM 专线产品拓扑
* **专线直出模式**：  
  流量经国内移动公网入口进入，直接走 IX 专线到达日本出口落地：
  ```text
  客户端 ──> CM 移动公网入口 (NAT) ──> IX 专线 ──> 日本出口
  ```

#### (2) Dual 系产品拓扑
Dual 架构物理机位于日本本土，配备双网卡（专线网卡与日本网卡）。根据访问方式的不同，拓扑路径如下：

* **专线直出模式（走专线）**：  
  流量经由国内 CMIX 入口打入 VPS 的“专线网卡”，再通过“日本网卡”转发流出至目标网络：
  ```text
  客户端 ──> CMIX 入口 ──> 专线网卡 ──> 日本网卡 ──> 目标互联网
  ```

* **直连模式（不走专线）**：  
  客户端直接连接机器的日本公网 IP（直达日本网卡），全程不经过专线网卡（过 GFW，无专线加速）：
  ```text
  客户端 ──> 日本公网 IP (直连日本网卡) ──> 目标互联网
  ```

#### 产品特性对比

| 产品线           | 物理机位置 | 网卡与出口架构    | 流量走向与特性                                                               |
| :------------ | :---- | :--------- | :-------------------------------------------------------------------- |
| **单 CM 专线产品** | 中国大陆  | 单网卡、单一日本出口 | 所有流量经由国内 CM 入口打入，通过 IX 专线送达日本出口落地。                                    |
| **Dual 系产品**  | 日本本土  | 双网卡、双出口    | 兼具“专线”与“直连 VPS”双重属性。既可通过国内 CMIX 入口走专线（流经双网卡），也可通过日本公网 IP 直连（仅流经日本网卡）。 |

### 2. 面板中的 IP 作用说明

登录 NoBrand 后台管理面板后，根据购买的产品不同，会看到 2 个或 3 个 IP 地址：

1. **国内公网 CM 入口 IP** (China Mobile)：
   * 公网移动 NAT 入口，**每位用户固定分配 100 个端口**，且已做好了端到端的自动端口映射。
   * 配置代理节点时，**走专线必须填写这个 IP 作为 Server IP**。
2. **IX 外部入口 IP**：
   * 专线交换中心（IX）的对接入口，接入机制与普通公网不同。
   * **普通家庭宽带无法直接连接**，必须借助阿里云、腾讯云等大厂云服务器通过内网或 BGP 专线接入（即玩家常说的“自备前置机中转”）。未搭建前置机时请忽略该 IP。
3. **日本直连入口 IP（仅 Dual 产品线提供）**：
   * 绑定在物理机日本网卡上的本地公网 IP。
   * 用于直接将该机器作为常规日本 VPS 使用，走公网国际线路，不享受专线加速，过墙。

### 3. 流量计算规则

NoBrand 根据底层网卡架构的不同，流量计费规则如下：

| 产品线 | 计费模式 | 计费说明与举例 |
| :--- | :--- | :--- |
| **单 CM 产品** | **单一网卡双向计费 (In + Out)** | 服务器仅单张网卡，入站流量（In）与出站流量（Out）均计入套餐总消耗。 |
| **Dual 系产品** | **双网卡各自单向计费** | 专线网卡与日本网卡分别统计各自单向流经的流量。<br>**举例**：实际消耗 10G 流量，专线网卡与日本网卡各自计费 5G，面板合计扣除 **10G**。 |

### 4. 协议可用性说明

* **公网入口过滤机制**：NoBrand 的国内公网入口部署了针对常见代理协议的识别与阻拦策略。
* 本教程统一以 **Mieru 协议** 作为教学范例，该协议经过了长时间的兼容性和用户验证，可用性较高。

### 5. 避坑

> [!CAUTION]
> **操作细节，请务必仔细阅读：**
> 
> * 脚本在 VPS 内部运行时，无法读取您的入口 IP，请务必手动检查 NoBrand 控制面板中提供的移动入口 IP。
> * **翻车后果**：
>   * 在 **单CM专线** 上：客户端直接向出口发起请求，可能导致**无法连通**。
>   * 在 **Dual 系产品** 上：客户端会直接连向日本网卡，导致**变成公网直连，根本没有走 IX 专线**。
> * **正确姿势**：在脚本提示输入“客户端连接时使用的入口地址”和“客户端入口端口”时，**请手动粘贴控制面板给出的【移动入口 IP】以及分配给你的【端口】**。

## 二、脚本安装与快速唤出

使用 SSH 工具（如 PowerShell、Termius、FinalShell）以 `root` 权限连接你的 NoBrand 服务器，粘贴并执行以下命令：

```bash
curl -fsSLO https://github.com/ike-sh/NoBrand-OneClick/releases/latest/download/install-nobrand.sh
sudo bash install-nobrand.sh
```

脚本会自动完成系统环境依赖（`jq`、`curl`、`flock` 等）的安装，并在 `/usr/local/bin` 中注册全局管理命令。

### 日常唤出菜单
以后任何时候需要修改配置或查看节点，在终端输入以下快捷命令即可唤出控制台：
```bash
sudo nb
# 或输入完整命令
sudo nobrand
```

在主菜单中输入 `1` 并敲回车：
```text

  0) 退出
请选择 [0-10]: 1
```
输入 `1` 并敲回车，进入新装参数收集流程。

---

### 第二步：选择配置预设（Profile）

```text
配置预设（真实参数仍会完整保存；之后单独修改参数会自动变为高级自定义）:
  1) IPLC / 专线性能 — IPLC、企业专线、明确允许使用的网络
  2) 普通公网 — 普通 VPS / 公网环境
  3) 强化伪装 — 更强 traffic-pattern；Low Entropy 仍默认关闭
  4) 高级自定义 — 逐项配置全部高级参数
请选择 [1-4，默认 2]:
```

> 💡 **注释**：
> * **选项 1 (IPLC / 专线性能)**：关闭了高算力开销的流量混淆，专为内网低延迟专线设计，吞吐性能更高。
> * **选项 2 (普通公网)**：保留轻量流量混淆。
> * **操作建议**：NoBrand 底层为 IX 专线，直接输入 `1` 敲回车（或输入 `2` 走保守模式均可）。

---

### 第三步：输入本地监听端口（结合 100 个分配端口）

```text
监听端口 [54321]: 
```

> 💡 **注释**：
> * 这是服务在当前 VPS 系统内部真实监听的端口，默认情况下脚本会自动扫描您的端口，并自动分配一个可用端口，请核对端口号是否在 NoBrand 控制面板提供的范围中。
> * **重要原则**：NoBrand 为你分配了 100 个端口（例如 `10200` 到 `10299`）。此处的端口**必须填写在这个区间内**（如输入 `10201`），这样才能保证机房前端的端到端映射生效。
> * 输入你的端口号后敲回车，或核对官网面板后保持默认回车。

---

### 第四步：手动指定公网入口 IP（关键步骤）

服务会输出本地 IP 探测信息，并提示输入客户端入口：

```text
检测到服务器公网 IP: 203.0.113.5
客户端入口只用于节点展示/导出，不会修改 mita 监听、firewall 或 tc。
如前面有 IPLC/NAT/端口映射，请在这里填写用户真正连接的入口；输入 auto 可恢复自动探测。
客户端连接时使用的入口地址 [203.0.113.5]: 
```

> 💡 **注释**：
> * **不要直接敲回车！** 方括号中检测到的 IP（如 `203.0.113.5`）仅仅是机器出口读取到的地址。
> * **操作方式**：打开你的 NoBrand 网页控制面板，找到分配给你的 **【移动入口 IP】**（如 `211.136.x.x`），手动输入或粘贴到此处回车。

---

### 第五步：手动指定公网入口端口

```text
客户端入口端口 [10201]: 
```

> 💡 **注释**：
> * 该端口会写入客户端配置文件中，供手机和电脑连接。
> * 默认情况下，NoBrand 的前端端口映射规则为**内外同号**（即外网映射端口与内网监听端口一致）。
> * 确认方括号内的端口对应于你分配的公网映射端口后，直接按回车；如果有指定映射端口，请如实输入后按回车。

### 第六步：自动安装与服务启动

完成上述交互后，脚本进入全自动化部署阶段：
1. 系统自动生成随机高强度用户名与连接密码。
2. 自动下载并校验官方 Mita runtime 稳定版二进制文件。
3. 自动配置 `systemd` 开机自启服务，并在本地防火墙中放行相应端口。

## 四、节点查看与客户端配置导入

安装完成后，你可以随时提取节点配置。

### 1. 命令行快速调出
在终端直接执行：
```bash
sudo nb nodes
```
或者进入交互主菜单选择 `10) 查看全部节点`。

### 2. 验证配置准确性
在将节点导入客户端前，请务必核对以下两项：
* **Server / 地址**：必须是 NoBrand 后台的 **移动入口 IP**。
* **Port / 端口**：必须在分配给你的 **100 个专线端口范围** 之内。

### 3. 支持的客户端软件
* **Mihomo 内核客户端**：Clash Verge Rev、Mihomo Party、Flclash 等（直接复制 YAML 格式的节点片段放入 `proxies` 列表）。
* **Mieru 官方客户端**：可直接使用输出的 Mieru Client JSON 配置。
* **移动端**：部分支持 Mieru 协议的客户端支持直接扫描终端二维码或解析 `mierus://` 链接。

## 五、日常运维与多用户管理命令

NoBrand-OneClick 将所有的运维操作封装到了统一的 CLI 与菜单中：

### 1. 状态自检与故障排查
```bash
# 查看所有已管理协议的当前运行状态
sudo nb status

# 对服务运行状态、本地监听占用及防火墙做全量健康诊断
sudo nb doctor
```

### 2. Mieru 用户管理（配额与限制）
在终端运行 `sudo nb` -> 选择 `1) Mieru` -> 选择 `3) 用户管理`：
* **添加新用户**：可独立生成账号密码，分发给不同设备。
* **设置流量配额**：支持限制每月使用流量（如 500GB，支持滚动周期或自然月重置）。
* **设置最大带宽**：支持为指定用户限定速率（Mbps），避免单个设备跑满专线带宽。

### 3. 修改展示入口（Display Endpoint）
如果服务商调整了前置公网入口 IP，无需重装节点，直接执行入口修改：
```bash
sudo nb mieru user-set-endpoint
```
按提示重新输入新的公网入口 IP 与端口，脚本会自动批量更新全部导出信息与配置文件。

### 4. 统一备份与安全卸载
```bash
# 创建全套配置、凭据与状态的完整备份包
sudo nobrand backup create

# 彻底卸载清理（仅删除本工具创建的服务与配置，保留系统核心环境）
sudo nobrand uninstall -y
```

## 六、新手高频踩坑与排错清单

### 1. 客户端显示连接超时 / Handshake Timeout？
* **第一检查项**：检查客户端填写的 IP 是不是出口日本 IP。如果填错了，请重新执行 `sudo nb mieru user-set-endpoint` 纠正为移动入口 IP。
* **第二检查项**：检查端口是否超出了分配的 100 个端口范围。公网入口设备只对分配范围内的端口做双向映射转发，超出范围的数据包会在入口机房被直接丢弃。

### 2. Dual 产品线用户测速发现“没走专线”？
* Dual 产品线同时存在“移动入口”与“日本直连入口”。
* 如果在配置客户端时使用了日本直连入口 IP，连接将直接走公网去往日本，绕过了 IX 内网专线，高峰期网络表现会显著下降。
* **排查办法**：运行 `sudo nb nodes`，确认输出中的 `server:` 字段是否为你面板上的**国内公网入口 IP**，而非机房分配给你的日本物理机直连 IP。
